El Diagnóstico Definitivo: El Caos de los Relojes Desincronizados

Vamos a analizar las pruebas que tienes delante. Son la historia de un sistema que está completamente desorientado en el tiempo.

1. La Prueba Visual (La Imagen):

Navigation: active: ¡Éxito! Todos los nodos de Nav2 se han iniciado correctamente.

Localization: inactive: ¡El síntoma principal! Nav2 sabe que no está localizado.

La Nube de Puntos Verdes: Es el Amcl Particle Swarm. Las partículas son las "hipótesis" de AMCL sobre dónde está el robot. Cuando están esparcidas por todo el mapa como en tu imagen, significa que AMCL no tiene confianza en ninguna posición. Está completamente perdido.

2. La Prueba de la Consola (La Causa Raíz):
Estos dos errores, que se repiten, son la "pistola humeante":

[amcl-1]: Message Filter dropping message: frame 'oak-d-base-frame' ... for reason 'the timestamp on the message is earlier than all the data in the transform cache'

[controller_server-4]: Message Filter dropping message: frame 'oak-d-base-frame' ... for reason 'the timestamp on the message is earlier than all the data in the transform cache'

Traducción al español (la más importante de todas):
El nodo amcl (y el controller_server) está diciendo:

"Acabo de recibir un paquete de datos del sensor (/scan, que se origina en la cámara oak-d-base-frame) con una marca de tiempo de, digamos, 10.5 segundos."

"Para poder usar este dato, necesito saber dónde estaba el robot (base_link) en el mapa en ese mismo instante, 10.5 segundos."

"Le pregunto al sistema de transformadas (TF), pero el último dato que tiene de la posición del robot es de, digamos, 10.6 segundos."

"¡El dato del sensor es del pasado! No puedo viajar en el tiempo para colocarlo en el mapa. Por lo tanto, lo tiro a la basura (dropping message)."

Conclusión Irrefutable:
El driver de tu cámara y el sistema de odometría están estampando sus mensajes con un "reloj", mientras que el resto de tu sistema ROS 2 está usando otro. Este desfase, aunque sea de milisegundos, es fatal para los nodos que necesitan sincronizar datos, como AMCL. Como AMCL está descartando todos los datos del sensor, nunca puede comparar lo que ve con el mapa, y por lo tanto, nunca puede localizarse.

La Solución Final y Definitiva: use_sim_time

La solución estándar de ROS 2 para este caos es forzar a todos los nodos a usar un único y centralizado "reloj maestro". Esto se logra con el parámetro use_sim_time.

import os
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription
from launch_ros.actions import Node
from launch.launch_description_sources import PythonLaunchDescriptionSource

def generate_launch_description():
    robot_driver_prefix = get_package_share_directory('robot_driver')
    map_file = os.path.join(robot_driver_prefix, 'mapas', 'Mapa_Lab.yaml')
    nav2_params_file = os.path.join(robot_driver_prefix, 'config', 'Parametros_Nav2.yaml')

    # --- ¡LA SOLUCIÓN CLAVE! ---
    # Le decimos a toda la pila de Nav2 que use el reloj simulado
    nav2_launch = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(get_package_share_directory('nav2_bringup'), 'launch', 'bringup_launch.py')
        ),
        launch_arguments={
            'map': map_file,
            'params_file': nav2_params_file,
            'use_sim_time': 'true', # <-- ¡CRÍTICO! Cambiado a 'true'
        }.items()
    )

    # El resto de los nodos también deben usarlo.
    # El lanzador de odometría debe ser modificado para aceptar este argumento.
    # (Lo haremos en el siguiente paso)
    odometry_launch = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(
            os.path.join(robot_driver_prefix, 'launch', 'odometry.launch.py')
        ),
        launch_arguments={'use_sim_time': 'true'}.items()
    )

    robot_driver_node = Node(
        package='robot_driver',
        executable='robot_driver_node',
        name='robot_driver_node',
        output='screen',
        parameters=[{'use_sim_time': True}] # <-- ¡CRÍTICO!
    )
    
    depthimage_to_laserscan_node = Node(
        package='depthimage_to_laserscan',
        executable='depthimage_to_laserscan_node',
        name='depthimage_to_laserscan',
        remappings=[
            ('depth', '/oak/stereo/image_raw'),
            ('depth_camera_info', '/oak/stereo/camera_info'),
            ('scan', '/scan')
        ],
        parameters=[{'output_frame': 'oak-d-base-frame', 'range_min': 0.3, 'use_sim_time': True}] # <-- ¡CRÍTICO!
    )

    rviz_node = Node(
        package='rviz2',
        executable='rviz2',
        name='rviz2',
        arguments=['-d', os.path.join(get_package_share_directory('nav2_bringup'), 'rviz', 'nav2_default_view.rviz')],
        parameters=[{'use_sim_time': True}] # <-- ¡CRÍTICO!
    )
    
    return LaunchDescription([
        odometry_launch,
        robot_driver_node,
        depthimage_to_laserscan_node,
        nav2_launch,
        rviz_node
    ])
